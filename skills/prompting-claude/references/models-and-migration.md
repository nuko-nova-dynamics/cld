# Claude models and migration notes

Checked against Anthropic's platform docs on 2026-09-23. This reference supports Claude delegation through this plugin's Claude Code runner. The Messages API notes below apply only to integrations that build API requests or agent loops themselves. Model and effort choices are starting points to evaluate, not results verified on this repository's tasks.

## Current model choices

| Model | Claude API ID | Starting point | Default effort | Context / max output | Base input / output per million tokens |
| --- | --- | --- | --- | --- | --- |
| Opus 5.5 | `claude-opus-5-5` | Most workloads, including long-running coding and knowledge work | `medium` | 1M / 128K | $4 / $20 |
| Fable 5.1 | `claude-fable-5-1` | Demanding reasoning or long-horizon work when Opus 5.5 at higher effort falls short on your evaluations | `high` | 1M / 128K | $10 / $50 |
| Sonnet 5 | `claude-sonnet-5` | Speed and intelligence balance | `high` | 1M / 128K | $2 / $10 |
| Haiku 4.5 | `claude-haiku-4-5-20251001` | Fastest current model | Not supported | 200K / 64K | $1 / $5 |

Source: [Anthropic's current models overview](https://platform.claude.com/docs/en/models/overview). The table gives Claude API IDs and standard base rates, not a promise that the same string is accepted by every provider or by an installed Claude Code version. Check the [model's platform availability](https://platform.claude.com/docs/en/models/opus-5-5/whats-new-opus-5-5#availability) before pinning it elsewhere. Claude Mythos 5.1 has Fable 5.1 capabilities but is limited to [Project Glasswing participants](https://platform.claude.com/docs/en/models/fable-5-1/whats-new-fable-5-1#models).

For this plugin, leave `--model` and `--effort` unset when the user's Claude Code configuration should decide. If a task needs a deliberate model choice, run representative tasks before changing a standing default. `--effort` is a Claude Code CLI option passed through by this runner; the Messages API uses `output_config.effort`. Do not treat the API examples below as runner flags.

## Agent decision rules

| If you observe or need | Use this rule |
| --- | --- |
| No model preference or benchmark | Leave the runner's model and effort unset. For a new direct API workload, start evaluating Opus 5.5 at `medium`. |
| Hard reasoning or a long agent run misses its completion checks | Try higher Opus 5.5 effort, then evaluate Fable 5.1 at `high` on the same task. |
| Cost or latency is high but quality passes | Test one lower effort level on the same model before changing models. Record task completion and total cost. |
| Fable 5.1 at `low` answers from memory on current facts | Require retrieval or raise effort for that turn. |
| A long run ends with a progress report or asks for already authorized permission | Check outstanding work and continue within scope; do not count the report as completion. |
| A small Fable 5.1 edit rewrites whole files or adds unrelated tests | Ask for targeted edits and tests sized to the requested behavior. |
| A custom Fable 5.1 tool loop calls independent tools one at a time | Add a one-line batching instruction after tool results while preserving earlier turns. |
| You are changing a direct API model, provider, or tool loop | Use the migration section below and test its request shape. Do not copy API settings into the CLI runner. |

## Prompt for the model in use

**Opus 5.5.** Start at `medium`; test `low`, `high`, `xhigh`, and `max` only where the task warrants them. Effort names do not imply the same thinking depth across models. At the same named effort, Opus 5.5 can think more per turn than Opus 5, especially at `xhigh` and `max`. Lower effort before adding prompt text that asks it to think less. Give long agentic tasks an explicit completion condition and check that a progress report did not end an unfinished run. For work with tools, ask for opening and intermediate updates when the user needs visibility. [Opus 5.5 prompting guide](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-opus-5-5#calibrate-effort), [unattended runs](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-opus-5-5#unattended-agentic-runs), [progress updates](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-opus-5-5#user-facing-progress-updates).

**Fable 5.1.** Start at `high`, then test all available levels against the same tasks. `medium` or `low` may preserve enough quality at lower cost, but at `low` the model searches and retrieves less often; explicitly require current-source checks when freshness matters. For long agentic work, state that authorized reversible steps should be completed before the final reply, while keeping the request's scope. Ask for progress updates if useful, and give a short instruction to batch independent tool calls if a custom agent loop issues them one at a time. For small text edits, ask for targeted changes. [Fable 5.1 prompting guide](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-fable-5-1#consider-all-effort-levels), [completion](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-fable-5-1#finish-the-whole-task), [scope and tests](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-fable-5-1#keep-changes-and-tests-to-what-the-task-asks-for), [search at low effort](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-fable-5-1#search-triggering-at-low-effort).

**All current models.** Describe the goal, relevant context, constraints, and what counts as done. Give ordered steps when their order or completeness matters; otherwise let the agent choose implementation steps. Examples and XML tags help with complex prompts that mix instructions, source material, and data. Put long source documents before the question. Tell the model explicitly when to use a tool or make an edit; a request for suggestions can yield suggestions only. [Prompting best practices](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices#be-clear-and-direct), [tool use](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices#tool-usage).

## Direct Messages API migration only

Claude Code manages its own Messages API requests, tool history, and progress display. The following is for a separate application that calls Anthropic directly. It is not a reason to add API parameters to `scripts/claude-run.mjs`.

**Opus 5 to Opus 5.5.** Change the ID to `claude-opus-5-5`. Thinking is always adaptive: `thinking: {type: "disabled"}` and manual `enabled` with `budget_tokens` return HTTP 400. Omit `thinking` or use adaptive thinking and control depth with `output_config.effort`; the default moves from Opus 5's `high` to `medium`. `tool_choice` types `any` and `tool` return 400; use `auto` with a clear tool instruction, strict tool use, or structured output. Strict tool use constrains arguments when a call occurs; it does not force a call. On the Claude API and Google Cloud, `computer_20251124` is unsupported; migrate to `computer_toolset_20260801` and update result handling. Amazon Bedrock retains the older computer tool for this model. [Opus 5.5 migration guide](https://platform.claude.com/docs/en/models/opus-5-5/migration-guide#migrating-from-claude-opus-5).

**Fable 5 to Fable 5.1.** Change the ID to `claude-fable-5-1`. The API surface, limits, tokenizer, base input/output rates, and always-on adaptive thinking carry over, but forced `tool_choice: any|tool` returns 400. Use `auto` plus a tool instruction and `strict: true` when schema-conformant tool input matters. If the tool was forced only to obtain JSON, use structured outputs instead. Fable 5.1 cache reads cost $0.25 per million tokens, one quarter of Fable 5's cache-read rate; compare total task cost, not base rates alone. [Fable 5.1 migration guide](https://platform.claude.com/docs/en/models/fable-5-1/migration-guide#migrating-from-claude-fable-5-to-claude-fable-5-1), [pricing](https://platform.claude.com/docs/en/models/fable-5-1/whats-new-fable-5-1#pricing).

**Sonnet 4.6 to Sonnet 5.** The new tokenizer yields about 30% more tokens for the same text, so recount representative inputs and resize budgets. Adaptive thinking is on by default; manual `budget_tokens` thinking returns 400, while `thinking: {type: "disabled"}` remains available. Non-default `temperature`, `top_p`, and `top_k` return 400. Assistant prefills already failed on Sonnet 4.6 and still do; use structured outputs or direct format instructions. Read response blocks by `type`, since thinking can precede text. [Sonnet 5 migration guide](https://platform.claude.com/docs/en/models/sonnet-5/migration-guide#migrating-from-claude-sonnet-4-6-to-claude-sonnet-5).

**From older models.** Do not assume an Opus 4.x or Sonnet 4.x request can move directly by changing its model ID. Opus 5.5 and Fable 5.1 reject assistant prefills, non-default sampling parameters (`temperature`, `top_p`, `top_k`), and manual thinking budgets; the tokenizer introduced before these models can also change token counts. Remove obsolete settings, use schema-constrained output or explicit formatting instructions in place of prefill, and size budgets from new token counts. Follow the migration path for the exact source model. [Opus 5.5 migration guide](https://platform.claude.com/docs/en/models/opus-5-5/migration-guide), [Fable 5.1 migration guide](https://platform.claude.com/docs/en/models/fable-5-1/migration-guide).

**Preserve the conversation.** In a direct API tool loop, append assistant responses exactly as returned, including thinking blocks, then append tool results. Fable 5.1 thinking blocks are tied to their producing model and the exact preceding conversation. Editing earlier messages, system text, tools, or prior tool results can invalidate them and return 400 for accounts created on or after 2026-08-31. Opus 5.5 also has model and conversation binding. Older-model fallback may drop newer models' thinking blocks, so the request can succeed while the model replans without that reasoning. Use append-only messages or Anthropic's server-side compaction and context editing. [Fable 5.1 migration guide](https://platform.claude.com/docs/en/models/fable-5-1/migration-guide#fable-5-1-preserved-thinking), [Opus 5.5 migration guide](https://platform.claude.com/docs/en/models/opus-5-5/migration-guide#migrating-from-claude-opus-5).

**Render progress and finish states.** Opus 5.5 and Fable 5.1 send between-tool narration as progress-update `thinking` blocks. Their default `thinking.display: "omitted"` leaves those blocks' text empty. An API UI that needs the updates should request `display: "updates"` with the `thinking-display-updates-2026-08-18` beta header and render non-empty thinking blocks before each tool call. A text-only `end_turn` can be a progress report on an unfinished task; check the completion condition and continue a bounded number of times. Handle `stop_reason: "refusal"` as a response state. [Opus 5.5 migration guide](https://platform.claude.com/docs/en/models/opus-5-5/migration-guide#text-between-tool-calls), [Opus 5.5 unattended runs](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-opus-5-5#unattended-agentic-runs), [Fable 5.1 progress](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-fable-5-1#ask-for-user-facing-progress-updates).

**Size output and check provider support.** Thinking tokens count toward `max_tokens`, even when hidden, so a limit sized only for visible text can truncate long outputs. Check each model's maximum and the target provider's ID and tool support before migrating. Model-specific behavior measured on Anthropic's platform is a hypothesis for a different provider or Claude Code installation until tested there. [Opus 5.5 effort guidance](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-opus-5-5#calibrate-effort), [model availability](https://platform.claude.com/docs/en/models/opus-5-5/whats-new-opus-5-5#availability).

**Change effort without rebuilding history.** Changing top-level `output_config.effort` invalidates a cached prefix. Opus 5.5 and Fable 5.1 support beta per-message effort via an empty system message with `output_config.effort` and `mid-conversation-output-config-2026-07-01`. Use that supported mechanism for adaptive routing rather than rewriting earlier messages. Confirm provider support and beta headers. This is an API technique, not a guarantee about what a resumed CLI invocation preserves. [Effort and per-message changes](https://platform.claude.com/docs/en/build-with-claude/effort#change-effort-mid-conversation-beta).

**Revisit old prompt workarounds.** Fable 5.1 can produce dense prose and less formatting; remove inherited blanket anti-formatting rules when structure improves readability. Ask for source paraphrases with short, marked quotations rather than copying retrieved passages. For either model, do not ask for a private reasoning transcript. For dense visual inputs, provide actual crop/zoom tools when available rather than claiming the model can inspect details through prompting alone. [Fable 5.1 writing and retrieval](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-fable-5-1), [Opus 5.5 vision and reasoning](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-opus-5-5).

## Evaluate before changing defaults

Use a small set of actual delegation tasks: one routine fix, one difficult multistep task, one review, and one long-context or document task if those occur in practice. Run each candidate model at its default effort first, then adjacent levels and `xhigh` or `max` only where quality might justify them. Keep prompts, input artifacts, tools, and completion checks the same. Record whether the requested artifact was completed, verification and review findings, refusals or early stops, model actually used after fallback, input/output and cache tokens, wall time, and billed cost. Compare cost per completed task and the quality of the artifact, not raw token price or subjective first impressions. For API integrations, re-count tokens when switching tokenizers and include hidden thinking and cache usage. [Choosing a model](https://platform.claude.com/docs/en/models/overview), [Opus 5.5 effort guidance](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-opus-5-5#calibrate-effort), [Fable 5.1 effort guidance](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-fable-5-1#consider-all-effort-levels).
